# Data and operations

1. Capture the universe and FX independently. The ranking is provider-defined global USD issuer market cap and delayed, with no synchronized exchange close guarantee. FX uses the most recent available Frankfurter observation on or before the UTC capture date, at most five calendar days old. The first load is a research snapshot rather than a trade-time quote feed.
2. Resolve listing aliases to issuer CIK or LEI. Exact SEC CIK duplicates cause the run to stop rather than double count. Non-SEC issuers without a validated key are visible with a gap; the provider symbol is a temporary identity, not a permanent key. The next security master should store exchange MIC, local symbol, ISIN, instrument/share class, issuer linkage, ADS ratio, FX and effective dates separately.
3. Prefer structured filing facts: [EDGAR Company Facts](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) for US GAAP and IFRS filers, [XBRL International](https://filings.xbrl.org/) ESEF JSON for supported LEIs. A small reviewed set of dated official issuer statements fills gaps; it expires under the same freshness rule. Latest usable annual statement wins. Manual observations are source-linked and tracked in `issuer-annual.json`; no program assumes these observations refresh themselves.
4. Select fiscal-year date, reporting currency, and accession before selecting concepts. Filter on filing availability and actual duration, exclude dimensional ESEF facts, resolve standard alias order, omit contradictory observations, preserve concept, filing URL, unit/currency and raw-content hash. SEC Company Facts omits custom tags, many inline-only facts, and some current filings. Dates from ESEF repository ingestion are conservative publication bounds when direct dates are absent. The annual as-of screen is not a point-in-time backtesting database: retroactive changes, restatements, survivorship and filing timestamps need dedicated treatment.
5. Compute model applicability and readiness separately. Statements older than 465 days do not feed valuations. Comparable-company joins use pre-indexed groups; the source cache is hashed, throttled, and reused across universe sizes. Cache files, receipts, snapshots and local overrides stay in ignored directories. For larger runs, ingest bulk SEC Company Facts where reachable and store normalized observations in partitioned tables keyed by issuer, filing and period. Migrate the static snapshot to per-issuer JSON shards or a query API before shipping many thousands of rows.
6. Publish the filings-only dataset using a separate export. Tests and an 80% fresh-coverage gate protect the existing deployment from poor source responses. A reviewed seed exists for manual deployment if public runners cannot reach SEC. The seed cannot be mistaken for a new refresh; its date travels with it.

The next gate before production at 1,000 is ≥90% recent annual filings across the largest 100 and ≥85% in the expansion, verified venue/share-class IDs, representative review in each major region and business group, and no systematic denominator or cash-flow bridge errors. Prefer a license that covers global issuer fundamentals, current/delayed quotes, corporate actions and public display. Then add quarterly LTM with filing timestamps, region-specific risk rates, segment/SOTP, capital-return histories, cyclicality by driver and persisted data revisions. The ranking parser accepts top 1,000, top 2,000 and `--floor 800000000`; these are supported input sizes, not proven valuation coverage.

Sources: [SEC ticker and fair access notes](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data), [CompaniesMarketCap download](https://companiesmarketcap.com/?download=csv) and [terms](https://companiesmarketcap.com/terms-of-service/), [Frankfurter API](https://frankfurter.dev/), [XBRL International API](https://filings.xbrl.org/api/filings). The SEC ticker file returned HTTP 403 in the pilot; the cache used the [sec-cik-mapper mirror](https://github.com/jadchaar/sec-cik-mapper), with overrides verified against SEC or GLEIF primary identifiers. Legacy ADR facts are subject to staleness checks.
